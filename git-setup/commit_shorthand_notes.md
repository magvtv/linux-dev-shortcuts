# Git Commit Shortcuts and Guidelines

## Commit Types

### 1. **feat**
   - **Description**: Introduces a new feature or functionality to the codebase.
   - **Prompt**: Use when adding a new feature.

### 2. **fix**
   - **Description**: Fixes a bug or an issue in the code.
   - **Prompt**: Use when fixing a bug.

### 3. **chore**
   - **Description**: Routine tasks like updating build scripts, package info, etc.
   - **Prompt**: Use for changes that don't modify src or test files.

### 4. **perf**
   - **Description**: Performance improvements to enhance functionality.
   - **Prompt**: Use when optimizing performance.

### 5. **docs**
   - **Description**: Updates or adds documentation only.
   - **Prompt**: Use when writing or editing documentation.

### 6. **style**
   - **Description**: Code style changes (whitespace, formatting, etc.).
   - **Prompt**: Use when making code styling changes.

### 7. **refactor**
   - **Description**: Code refactoring without changing any functionality.
   - **Prompt**: Use when restructuring code.

### 8. **test**
   - **Description**: Adding or updating tests without impacting production code.
   - **Prompt**: Use when writing or editing tests.

### 9. **hotfix**
   - **Description**: Critical fix quickly applied to the codebase.
   - **Prompt**: Use for urgent bug fixes.

### 10. **revert**
   - **Description**: Reverts a previous commit.
   - **Prompt**: Use when undoing changes.

## Best Practices

- **Write a concise commit message**: Maintain a short title followed by a detailed explanation if necessary.
- **Keep changes small**: Group similar changes together for cleaner history.
- **Active voice**: Use active voice, explaining what the commit does.

This guide should help you decide which commit type to use and maintain a clean git history.
