# Branch Naming Conventions & Developer Assessment

## Branch Naming Best Practices

Based on analysis of your projects, here's a recommended standardized approach to branch naming:

### Main Branches
- `main` - Production-ready code
- `develop` - Development integration branch
- `staging` - Pre-production testing

### Feature Branches
- `feature/short-description` - New features
  - Example: `feature/user-authentication`
  - Example: `feature/payment-gateway`

### Bug Fix Branches
- `bugfix/issue-description` - For fixing bugs
  - Example: `bugfix/login-redirect-loop`
  - Example: `bugfix/mobile-layout-overflow`

### Hotfix Branches
- `hotfix/issue-description` - Urgent production fixes
  - Example: `hotfix/security-vulnerability`
  - Example: `hotfix/api-timeout`

### Release Branches
- `release/version-number` - Release preparation
  - Example: `release/1.2.0`
  - Example: `release/2021-Q2`

### Refactor Branches
- `refactor/component-name` - Code improvements
  - Example: `refactor/authentication-flow`
  - Example: `refactor/database-queries`

### Chore Branches
- `chore/task-description` - Maintenance tasks
  - Example: `chore/update-dependencies`
  - Example: `chore/cleanup-assets`
